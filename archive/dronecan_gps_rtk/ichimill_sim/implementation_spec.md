# 実装仕様書：Windows PC用 ichimill 擬似通信・RTCMログ記録プログラム（修正版）

## 1. プログラム概要
本プログラムは、Windows PC上で動作し、NTRIPサーバー（ichi-mill）と通信を行う。実際のGNSSレシーバーの代わりに、指定された固定座標を「自分の位置」として擬似的に生成し、それをVRS方式で送信することでRTCM補正データを取得する。取得したRTCMデータはバイナリ形式でログファイルに記録される。

## 2. 主要機能
### A. NTRIPサーバー接続（HTTPヘッダー分離対応）
- **接続先**: `ntrip.ales-corp.co.jp` (ポート: `2101`)
- **マウントポイント**: `RTCM32MSM7`（または `RTCM31`）
- **認証**: ユーザー名・パスワードを `config.json` から読み込み、Basic認証を行う。
- **ヘッダー処理**: 受信スレッドにおいて、HTTPレスポンスのヘッダー部分（`\r\n\r\n`まで）を識別し、以降の純粋なRTCMバイナリストリームのみをログ保存対象とする。

### B. 擬似位置情報の生成と送信 (VRS対応)
- **固定座標**: 緯度: `36.077240`, 経度: `136.211767`
- **動作**: VRSサーバーの要求に応じ、**1秒〜2秒周期**で擬似的なGGAメッセージを生成し送信する。
- **NMEA変換ロジック**: 
    - 10進数の度（degree）を NMEA 規格の「度分（DDMM.MMMM）」形式に変換。
    - メッセージ末尾に XOR チェックサムを付与。
- **目的**: VRSサーバーに対し、自身の位置を正確に伝えることでRTCM補正データを引き出す。

### C. RTCMデータの受信とログ記録
- **受信処理**: サーバーから送られてくるRTCM3メッセージを受信。
- **ログ出力**: 受信したRTCMデータ（バイナリ）をタイムスタンプと共に `.rtcm3` 拡張子のファイルに**バイナリモードで直接保存**する。
- **監視表示**: 現在の接続状態、受信メッセージ数、送信回数をコンソールにリアルタイム表示する。

## 3. 技術要件・仕様
### 通信プロトコル
- **NTRIPプロトコル**: HTTPベースのストリーミング通信。
- **マルチスレッド構成**:
    1.  **受信スレッド**: NTRIPサーバーからのRTCMデータを受信し、ヘッダーを分離した上でバイナリログに書き込む。
    2.  **送信スレッド**: 擬似GGAメッセージを生成し、ソケットへ送信する。

### 使用ライブラリ
- `socket`: TCP接続用
- `base64`: NTRIP認証用
- `threading`: 並行処理用
- `json`: 設定ファイル読み込み用

## 4. ディレクトリ構成案
```text
ichimill_sim/
├── config.json               # 接続情報・認証情報・座標設定（git管理外）
├── main.py                   # メインプログラム
└── logs/                     # 受信した .rtcm3 バイナリログの保存先
```

## 5. 実装スケジュール（予定）
1.  **フェーズ1**: `config.json` の読み込みとNTRIP接続・認証、ヘッダー分離処理の実装。
2.  **フェーズ2**: 度分変換を含む擬似GGAメッセージ生成関数と送信ループの実装。
3.  **フェーズ3**: RTCMバイナリのパース（プリアンブル検知）およびファイル保存処理の実装。
4.  **フェーズ4**: テスト実行とログ確認。
