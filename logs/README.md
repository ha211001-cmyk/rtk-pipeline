# RTK Logs & Evaluation

このディレクトリは、RTK測位データの解析、評価、およびグラフ描画用スクリプトを格納しています。

## 📁 スクリプト群の説明

各スクリプトは以下の順序でデータを処理・評価するために使用します。

### 🚀 ワンクリック自動実行 (推奨)
- **`run_pipeline.sh`**: 下記の「解析のメインパイプライン」をすべて順番に自動実行するシェルスクリプトです。ターミナルで `./run_pipeline.sh` を実行するだけで、データ解析からレポート生成・グラフ作成までが完了します（※最後のグラフ作成にはMATLABのコマンドライン実行環境が必要です）。

### 1. 解析のメインパイプライン
- **`analyze_rtk.py`**: 生のCSVログを読み込み、データの全体から「真値（リファレンス座標）」となる平均座標を計算・定義するスクリプトです。
- **`evaluate_rtk.py`**: 定められた真値に対して、各時間区間（5分・20分・60分）のデータを切り出し、東西(E)・南北(N)・高さ(U)のズレ（誤差）を計算します。処理後の配列データはMATLAB用の `.mat` ファイルとして保存されます。
- **`generate_report.py`**: 計算された誤差データをもとに、RMSや標準偏差などの統計量を算出し、Markdown形式の評価レポート (`accuracy_report.md`) を自動生成します。
- **`plot_histograms.m`**: 保存された `.mat` ファイルを読み込み、MATLAB上で誤差のヒストグラムを生成します。VS Codeプレビュー用の `.png` とレポート用の `.pdf` を同時に自動保存します。

### 2. 生ログ抽出ツール
- **`parse_fc_log.py`**: PixhawkのSDカードに保存された生ログ（ArduPilotの `.bin` または PX4の `.ulg`）を解析し、GPSの週とミリ秒から絶対時間（UTC）を復元してCSVに書き出すツールです。後述する「超高精度データ」を抽出する際に使用します。

## ⚠️ データの分解能とグラフの形状について（重要事項）
`plot_histograms.m` で生成されたヒストグラムにおいて、分布に細かい隙間（櫛の歯状）が生じます。
これは分析や作図の不具合ではなく、**「MAVLink通信（GPS_RAW_INT）を用いた地上局ロギングに起因する、元データの分解能の限界」**によるものです。

現在の `mavlink_bridge.py` 経由で取得したログでは以下の丸めが発生しています。
- **緯度・経度 (水平)**: `10^7` の整数として送信されるため、距離換算で **約9〜11 mm間隔** の離散値となります。
- **高度 (高さ)**: 送信時・処理時の丸めにより、**10 mm間隔** の離散値となります。

データ自体が約1cm刻みのグリッドで記録されているため、1mm幅のヒストグラムを作成するとデータが存在し得ない隙間が生まれます。

## 💡 次回の定点テスト（飛ばさないテスト）に向けた注意点

上記の問題を解決するためには、地上局の通信ログではなく **「Pixhawkの内部SDカードの生ログ（.bin）」** を使用する必要があります。
しかし、**機体をARM（モーター起動）せずに長時間地面に置いたままにする「定点テスト」の場合、デフォルト設定のままではPixhawkはSDカードにログを一切書き込みません。**

次回以降のテストで確実に高精度なログを残すためには、テスト実施前にMission Planner等で以下のパラメータを変更してください。

1. **`LOG_DISARMED` = 1** に設定する
   * 電源を入れた瞬間から常にSDカードにログを書き込み続けるようになり、ARMしなくても定点テストのデータが保存されます。
2. **`LOG_BITMASK`** で生データを有効化する
   * `GPS_RAW` などの生データを記録するビットをONにしておくことで、1cmの丸めを回避した **0.1mm分解能** の最強データ（UBXメッセージ）がSDカードに記録されます。

テスト終了後、SDカードから `.bin` ファイルを取り出し、本フォルダの `parse_fc_log.py` を通すことで、ミリ単位で滑らかに分布する高精度な誤差評価が可能になります。
